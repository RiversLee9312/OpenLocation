# Internationalization

The controller translations are complete for default English, Simplified Chinese, and 20 additional locales. Each localized controller resource covers all 191 distinct translatable strings and the `route_points` plural, as well as all 41 probe strings. The interface includes route editing and place search, GPS track recording, a unified GPX track library, a system-service label in the target-app list, heading variation controls, GNSS provider labels and device-profile verification scope, and the first-use usage notice. Track names support 1–120 characters. See [the translation report](translation-report.md) for the locale list and validation details.

## Resource rules

- Never put visible text in Kotlin literals. Use `stringResource`, `pluralStringResource` or `Context.getString`.
- Use complete semantic strings and positional placeholders (`%1$d`, `%2$.1f`); do not concatenate translated fragments.
- Number formatting uses the current Android locale. Machine-readable exports keep JSON numeric values or locale-independent XML numbers.
- Movement and environment enum values remain stable wire identifiers; presentation labels live in UI resource mappings.
- Product names, hardware sensor names, standard provider identifiers and SI symbol names are not translated as arbitrary prose.
- Keep actions short. Translate Start/Pause/Resume/Stop consistently. Diagnostic limitations must retain their meaning.
- Use plurals for count-dependent text. Languages with multiple plural forms must provide their required categories.
- Use start/end spacing and wrapping rows. Test RTL, long German text, CJK and large system font size. Do not force an LTR whole screen to repair numeric fields.
- Declare all controller languages in `res/xml/locales_config.xml` so Android 13+ per-app language Settings can select them.

## Translation review

The translator must work from each module's English `values/strings.xml`, preserve every translatable key and placeholder type, escape apostrophes as required by AAPT, and provide translations for both controller and probe. Run `tools/check-locales.py` before building. Android lint and AAPT are required in addition to the structural checker. Language quality still benefits from native-speaker review; generated localization is not represented as human certification.
